# 频道详情分页修复验证

日期：2026-10-23（Asia/Shanghai）。本轮仅本地验证，未发布 Worker、未应用生产迁移、未访问真实 YouTube。无新增迁移。

## 修复行为

- `episodes`、`archive`、`jobs` 的 offset 不小于总数时取最后有效页；零条归零。30 条是单页，31–60 条的末页从 30 开始。有效的非整页 offset 仍保留；负数、小数、超过 1,000,000 等非法值仍返回 400。
- 分页计数与行查询保留在同一 D1 batch，SQL 内修正 offset，避免额外查询期间列表变化造成空页。D1 数值绑定按 SQLite 实数参与运算，页数计算显式转整数后再乘页大小。
- 前端收到修正后的 offset 后使用 `history.replaceState` 同步 hash，不重复请求、不新增浏览历史。来源列表不分页，offset 归零。
- 正常无数据与意外空页分别提示；意外空页提供“返回第一页”，不再显示伪造的条目范围。
- 真实删除验证发现：删除更新触发 GC 写入，D1 的 `meta.changes` 不能作为“恰好更新一个节目”的判断。改用 `UPDATE ... RETURNING id` 的结果确认成功；仍保留转码中返回 409 的保护。

“删除音频”保留节目身份供重新生成，因此正常节目列表不一定减条目；旧缓存仅包含仍有音频的记录，删除后会缩减。此次没有改变数据删除语义。

独立本地 Worker：`127.0.0.1:8793`；D1/R2 状态：`.wrangler/channel-pagination-state`；迁移 0001–0015。原 8787 预览与生产资源未改动。输入是本地 SQL fixture，音频对象为占位引用，本轮不验证播放、转码或实体手机。

## 复验

环境准备与变量见 [DEVELOPMENT.md](DEVELOPMENT.md)。先运行 `npm run check`、`npm test`，再对独立本地服务运行 `node tests/channel_detail.mjs`。需要界面 fixture 时加 `--keep`；该选项会保存本地测试凭据并保留资源，不适用于真实账号。

浏览器用 32 条节目验证 `/episodes/999`、上一页、下一页、后退、前进、刷新。旧缓存准备 31 条，进入 `/archive/30` 后删除唯一一条，确认退到 0 且剩 30 条；再用仅一条的缓存验证删至空列表。人工测试资源按准确 ID 清理，或停止专用服务后处理本轮独立测试目录；不要清空其他用户库。
