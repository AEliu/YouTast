# 处理任务与历史记录

2026-10-24。

## 展示规则

频道详情的“处理任务 N”统计待处理、处理中和真正失败的任务，与默认“当前任务”列表一致。全部完成且没有异常时为0。频道概览显示等待/处理中数量，并另列失败数量。

频道和全局任务页均可切换“当前任务 / 历史记录”，显示待处理、处理中、失败分项统计。已完成任务归入历史；来源暂停、退出最新N范围、用户删除音频、保留期到期清理及空间自动清理导致的任务停止显示“已停止”，归入历史，不提供任务重试按钮。需要重新生成音频时仍从节目入口操作；来源恢复和窗口扩大继续使用原有调度规则。

历史保留原记录。现有数据库将上述五类停止存为failed，根据准确匹配的服务端原因映射display_status=stopped；未知错误仍显示失败，不按模糊文本吞掉异常。最初分类功能没有数据库迁移；后续批量清理增加0018迁移，见下文。

## 批量重试与清理

频道与全局当前任务页支持：勾选失败任务、本页全选、重试所选、清理所选，以及处理当前频道/搜索范围内全部失败任务（包含其他分页）。单行也可清理。全部频道操作明确标注范围；正常停止、已完成、等待和处理中任务不能被批量清理或重试。

操作前从服务端读取实际匹配数量并确认。重试重置尝试次数、错误与开始时间，继续遵守执行器并发和请求节奏。同一来源的多个失败扫描只安排一次；暂停中或已有活动扫描的来源跳过，确认时说明跳过数量。任务数量发生变化返回409，提示重新确认，不部分执行。勾选任务期间暂停后台刷新，避免丢失选择；主动刷新或切页重新选择。

清理从当前和历史列表移除失败任务，不删除节目、来源、音频对象或媒体元数据。未生成音频的节目显示“已停止重试”，可从节目入口明确重新生成。迁移 `0018_job_dismissal.sql` 增加 `jobs.dismissed_at`，保留转换任务的唯一记录以阻止扫描/窗口校准自动重新入队；明确的节目重新生成才清除该标记。清理不暂停来源后续的自动同步，未来的同步失败属于新任务；需要停止自动发现可暂停来源。

API：`POST /api/jobs/bulk/preview` 和 `POST /api/jobs/bulk`。body包含action=retry/dismiss、ids（1–80个、不重复）或all=true（二选一），可选channel_id/query；执行还须提交preview返回的expected_count与expected_matched。筛选与列表共用搜索条件，服务端检查本人频道、CSRF、真实失败状态与确认数量。更新在单条SQL内完成，重复扫描去重后入队，避免违反活动扫描唯一约束。

## API与链接

- `/api/jobs` 和 `/api/channels/:id/detail?tab=jobs` 默认 `tasks=current`，不再返回已完成任务。
- `tasks=history` 返回已完成及正常停止记录；非法分类返回400。
- `status` 保留存储值，`display_status` 为页面状态。`counts.jobs` 为当前任务总数，另返回history、queued、running、failed、active；active仍仅queued+running。计数不随搜索缩小，分页总数按分类与搜索计算。
- 分类、搜索及分页写入hash，例如 `#channel/:id/jobs/30?q=keyword&tasks=history`；切换分类回第一页，搜索/清除搜索保留分类；刷新、前进/后退保留链接状态。
- 旧dashboard兼容数组仍按原有规则返回，网页不使用该数组展示任务列表。
