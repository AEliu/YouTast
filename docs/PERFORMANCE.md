# 页面性能优化与验证

2026-10-24。本轮处理频道详情等待时间及全站页面的重复请求，不改变来源窗口、音频缓存或分页规则。

## 瓶颈与修改

- 旧页面每次进入详情、分类、分页和搜索，先等待完整 dashboard，再请求当前页。现在首次请求并行；路由切换复用一分钟内的 dashboard，当前页始终重新请求。手动刷新、写操作后的刷新和定时刷新仍更新 dashboard。
- 新网页使用 `/api/dashboard?summary=1`，省略兼容接口的100条完整节目与80项任务；两数组返回空数组。未带该参数的旧接口保持原有内容和上限。
- 旧窗口视图先对全站节目做来源/频道排名，再由调用方过滤；首页相关子查询还重复计算它。页面查询改用 `src/window-query.js`：先限定频道或账号，再物化候选和窗口，只有有限量来源、频道需要排名；首页一次聚合全部频道的可听/缓存数量。全局视图继续供调度、RSS、清理等原有通路使用。
- 快速导航通过 AbortController 取消旧页面 GET，并校验响应对应的路由；搜索输入获得焦点时不进行定时重绘。

没有数据库迁移，最高仍为0017；执行器不需要更新。

## 可复现验证

`npm test` 包含两个新增数据库测试，合计25项通过。夹具为内存SQLite、20个频道、6,000条节目，当前频道300条，其他账号占16个频道。覆盖来源重叠、无限/有限窗口、未知日期、同日期、旧记录缺少来源映射、暂停不移除节目、用户偏好继承、分页与搜索，以及精简/兼容接口、账号范围和首页计数一致性。

可选基准需要Git中有旧提交 `fe2141f`，普通测试不依赖历史提交：

```powershell
$env:PAGE_BENCHMARK='1'
node --test tests/window-query.test.js
Remove-Item Env:PAGE_BENCHMARK
```

同一夹具、同一进程运行旧/新详情实现，断言返回对象完全相等。本机两次测得旧查询72/83 ms，新查询8/9 ms；完整dashboard JSON为201,622字节，精简版4,433字节，减少约97.8%。这是本地合成数据与SQL耗时，不包含真实网络、Cloudflare D1或页面绘制，不作为线上延迟承诺。

独立Wrangler `8801` / `.wrangler/performance-state` 依次通过：

- `tests/channel_detail.mjs`：详情分页、越界、删除后退页/清空、排序、缓存和权限。

- `npm run test:sources`：来源2/3条、合并上限、缓存复用、单独同步、暂停及租约。
- `npm run test:integration`、`tests/channel_sort.mjs`：完整音频/租约/Range/权限流程、排序与RSS。
- `npm run check`：语法与编译检查。

实际浏览器加载本地静态资源，以延迟响应的合成API验证：初始化两个请求相差1 ms启动；切换来源页没有新增dashboard请求；前一页延迟1,100 ms时，导航到任务页约324 ms完成，过时响应没有覆盖任务页；手动刷新重新请求dashboard；401回到登录页，无脚本异常。模拟API不构成生产用户体验测量。
